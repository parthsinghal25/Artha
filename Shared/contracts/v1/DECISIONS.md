# Shared contracts 1.0.0 — decisions for the replacement build

14 October 2026. Principal Architect. Review candidate until the adoption record identifies explicit Data/UI acceptance. This package specifies the build; it does not provide evidence files, model outputs, an API implementation or a working dashboard.

## Scope and authority

Build one complaints-leadership application for fictional Example Super. Customer care is a future reuse case. Permitted inputs remain Data v0.2's five kinds: party, case, source, procedure and coverage. Vendor call summaries are inputs; raw recordings, private conversations, writer instructions, incident/world tables, gold and archives are excluded. Originals/extractions/locators are companion records, not a sixth ingestion kind. Findings are analysis, never independent source evidence.

The baseline runtime schema, evaluation schema, metric registry and demo configuration are pinned by digest in the adoption manifest. This package adds interfaces and five reusable analytical measures plus seven member-experience measures. It never adds properties to a closed v0.2 object. Existing plans that defer AI **design** until the reviewed forty-member pilot are superseded by the participant's latest instruction: design may start after contract agreement. Actual evidence acceptance, evaluation, model execution and expansion retain their separate gates.

## 1. Identities, copies and business events — O-05

`source_id == envelope.record_id` identifies an immutable v0.2 source version; `logical_id` identifies its logical history. A logical document has immutable asset versions. Each extraction and preview has its own immutable identity. References always resolve an exact version; “latest” is resolved once and returned explicitly, never substituted during a drill-down.

Asset byte digest and source-content digest have different algorithms and purposes. Keep Data's canonical source hash unchanged, including native facts. A new extraction yielding identical accepted text may reuse the existing source binding; changed text/native facts creates a new source version, with new anchors. The old representation remains addressable only where permitted. Re-extraction does not create a business occurrence.

An attachment occurrence is one parent-source/child relationship, distinct from a submission, request, contact, task, work entry or payment occurrence. Embedded and separately stored bytes of the same attachment reuse one asset version where provenance and access agree; several forwards retain separate attachment edges. Content-hash equality alone never merges business occurrences. A forward is not another member submission. A genuine second member submission can be another occurrence even if its bytes are identical. Derive deduplication from explicit references and evidence; leave uncertain duplicates uncertain. Never deduplicate solely by date or filename.

`advertised_unheld` edges have null child assets and no placeholder bytes. Their advertisement requires a permitted citation. Attachment metadata is released only after child/advertisement authority checks. The server does not reveal denied identities or filenames through the parent.

## 2. Permissions, redaction and containers — O-02/O-03

Authorisation is server-owned. Authenticated principal plus current policy resolves the permitted view, opaque scope token, capabilities and permission revision. A requested view or model argument cannot grant access. All retrieval, search, aggregate, contributor, preview, mapping and cache operations recheck the current revision. Permissions must be backed by a trusted allowlist; the LLM cannot populate policy grants.

Default multi-case document policy requires authority for **every** case/matter and protected segment represented in that document. A trusted explicit per-document grant may override that default; authority for one linked case does not. Aggregate-only access is an explicit capability over an approved population, not inferred from case access. It exposes no case/source/attachment IDs or contributor handles to an unauthorised caller. Do not infer small-cell disclosure policy: first pilot has full complaints-role access plus deliberately denied test resources; aggregate-only publication requires an approved disclosure policy and stays unavailable without one.

Check complete requested representations recursively. An EML original containing a denied attachment or quoted segment cannot be downloaded merely because its parsed parent text is allowed. Withhold the original; alternatively publish a reviewed derived redacted file under a new asset identity/digest and an accurate label. Sanitising HTML does not remove an embedded attachment from EML bytes.

Redacted text/native facts receive a **new source identity and content hash**, with independently reviewed anchors and explicit lineage recorded in the release acceptance metadata. The full-access version is not globally superseded by a restricted view. Derived bytes, previews and citations are bound to the visible version. Restricted lineage is not returned to callers who cannot see its parent. Hashes establish integrity, not truth or anonymity.

No public bucket URLs, local paths, client-selected object keys or permanent bearer links. Opaque retrieval actions expire within five minutes and revalidate authority at use; source/view cache clears on scope/revision changes. Download requires a separate capability. HTML/EML/DOCX previews are sanitised and sandboxed, with scripts, forms, tracking and external loads disabled. XLSX formula values are read-only; never execute macros/formulas or remote links. Unsupported/encrypted files remain explicitly unavailable.

Internal `asset`, `extraction` and `attachment` records are never serialized wholesale into API inventory/source responses. Their closed public projections deliberately omit storage/policy/acceptance references and restrict source/asset/parent/copy links to separately authorised identities. A derived-redacted asset with a denied parent returns an empty permitted-parent list and `lineage_disclosure=limited`; it does not expose the parent's ID or digest. Public extraction can withhold its original asset ID/digest while exposing its independently valid permitted source; emitted-source links are filtered individually. Omission/lineage wording must not disclose protected filenames/content or hidden counts. Explicit document access does not automatically permit every referenced case/source: if the source-content's own hashed native/prose metadata needs redaction, publish a new reviewed visible source version rather than editing it under its original hash.

## 3. Real assets and extraction — O-04

Published held assets require actual validated bytes, size, digest, acceptance and trusted blob references. The assigned semantic format, declared MIME, detected container/signature and successful safe parser must agree. A filename alone is insufficient. CSV uses a registered parser profile: declared encoding/delimiter/header, proper quoting, and no spreadsheet execution. Any intentional conversion is a new labelled derived representation, not a renamed original.

Supported first-build formats: EML, PDF, CSV/XLSX, PNG/JPEG and call-summary TXT/DOCX. HTML is a safe derived preview. Actual parser support can be narrower initially, but the UI must disclose it. Representative EML with a reused attachment, PDF and financial extract precede full-format claims. Images/OCR and call-summary fidelity are validated before claiming the complete format catalogue.

Extraction records name the exact asset/digest, extractor/configuration, actual processing timestamp, source bindings, completeness and omissions. Pending/failed extractions emit no accepted source. Partial extraction may support reviewed passages with declared omissions, never assumed complete evidence. Acceptance of bytes, extraction and diagnosis is separate. No guessed digest, anchor, page, cell or outcome fills a pending field.

## 4. Citation and location conventions

Preserve v0.2 Unicode code-point spans, start inclusive/end exclusive, and JSON pointers. End must exceed start for a text citation; anchors must resolve within the exact visible source and hash. Convert code-point offsets correctly in JavaScript. JSON pointers resolve native facts under Data's convention; malformed/unresolved pointers fail.

Mappings bind citation → extraction → asset version/digest and validation record. Verified locations use:

| Format | Fixed convention |
|---|---|
| PDF | Page one-based; upright displayed crop box after declared rotation; top-left normalised rectangle. Whole-page mapping is valid and labelled page precision. |
| Image | Original dimensions and EXIF orientation; coordinates refer to the EXIF-normalised displayed image, top-left normalised. |
| XLSX | Original sheet ID/name and A1 range; sorted UI rows never change the original address. |
| CSV | Parsed data-record index one-based **excluding the header**; column index one-based. Quoted newlines do not create additional records. Parser profile identifies encoding/delimiter/header rules. Optional native key supplements the original record index. |
| EML | Root MIME part `0`; ordered children `.1`, `.2`, recursively. Headers/body/attachment separate; spans refer to the digest-bound decoded representation, not raw-byte offsets. |
| TXT | Digest-bound decoded text and code-point span. |
| DOCX | OOXML part name and one-based paragraph in document order; optional decoded paragraph span. No unstable rendered-page claim. |

Check page/cell/part existence, dimensions, ordered rectangle bounds and span bounds against the actual file. Incomplete mapping returns `unmapped`; invalid binding returns `invalid`. Neither returns guessed coordinates. A valid extracted citation remains usable without native mapping. Whole-original permission/availability is checked independently. No auto-search jump labelled as an exact location.

## 5. Three clocks and v0.2 crosswalk — O-01

All instants carry offsets; order in UTC; calendar arithmetic uses `Australia/Melbourne`, including DST. Half-open activity ranges and local-day boundaries remain. Date-only evidence never acquires an invented event time. Synthetic scenario document/recording/availability dates are explicitly fictional. Ingestion, extraction, computation and publication audit times remain actual.

| Existing field | Meaning retained / companion mapping |
|---|---|
| Input envelope `available_at` | Scenario time the evidence was available to the simulated role; bounded by `context.evidence_as_of`. Actual ingestion is separately audited. |
| Input occurrence/recording | Evidence proposition/event date and recording date, not analysis discovery. |
| v0.2 `query.snapshot` | Exactly the companion selected evidence cutoff; not publication time. |
| `finding.assessed_snapshot` | Evidence cutoff of that assessment. |
| Finding/output envelope `available_at`, `published_at` | Real output availability/publication. Never backdate to make replay nonempty. |
| `metric_result.computed_at` | Real calculation timestamp; companion also supplies real publication and versions. |
| `query.source_version` / `finding_version` | Immutable resolved input/analysis sets, with companion taxonomy and result versions; not file timestamps. |

This is an explicit companion adapter rule: **do not call the old combined-record snapshot filter unchanged on analysis outputs.** Input evidence and analysis publication have separate eligibility tests. The original Data fields/schema remain unchanged; the adapter is part of the future implementation and its compatibility tests are mandatory.

`reconstructed`: analyse permitted scenario evidence available by T, compute/publish now. Label “Reconstruction from evidence available by T; computed/published [actual date]”. `analysis_as_of` is null. It does not claim contemporaneous detection or a prototype operating in the past.

`as_reported`: additionally select only actual immutable analysis versions published/available by `analysis_as_of`. If none exists, return `HISTORY_UNAVAILABLE`; reconstruction is never a silent fallback. Input cutoff remains explicit and must be compatible with that stored analysis.

Flows use eligible events in the activity window known at selected T, and disclose late-recorded evidence. For stock at endpoint B, use scenario evidence available strictly before B, capped by T. Inventory is immediately before the exclusive B endpoint. Date-only availability on B cannot be assumed before B. Supported state/finding memberships must be reconstructed at that same cutoff, or selected from compatible stored as-reported history. One finding reconstructed at September cannot silently classify March stock. Each stock cell binds its own population and input/analysis-set lineage. Trend series can share taxonomy definitions, but never incompatible historical membership evidence.

## 6. Population, contributors and comparisons — O-06

Every query resolves a canonical immutable predicate plus SHA-256, result identity, definition, unit, actual clocks, coverage, algorithm and input-set digest. Each cell embeds `population_binding`: its complete predicate, typed AND-composed selectors, evidence boundary, endpoint-compatible assessment ID/cutoff, source/analysis/taxonomy/algorithm versions, input digest and actual computation/publication. The top-level predicate is only the common selection. Empty selectors mean no additional cell qualification; labels/keys never select cases. Typed selectors describe exact combinations, MX states/positions, taxonomy nodes, age/AFCA groups, matrix axes and known-duration subsets. Unsupported qualification requires an explicit schema extension, not a free-text label.

The cell predicate digest hashes canonical JSON of `{predicate, selectors, effective_evidence_as_of, evidence_boundary, versions, input_set_sha256, assessment_id, assessed_evidence_as_of, analysis_mode, analysis_as_of}`. Remove `predicate.population_id`, `predicate.population_version` and `predicate.population_sha256` before hashing; omit computation/publication timestamps from the selection digest. Sort object keys, compact separators and retain Unicode. Set both `population_binding.predicate_sha256` and `predicate.population_sha256` to this digest. Preserve the exact binding as an immutable published object. `population_id` on cell/binding/predicate and predicate version/binding version must agree. Predicate evidence cutoff equals the binding's effective cutoff. For stocks that cutoff and assessment equal the actual exclusive effective endpoint, with input evidence strictly earlier; a future requested bucket is truncated to the selected cutoff and visibly partial rather than extrapolated. For flows/populations, use the selected cutoff and its declared boundary. Real publication remains independent. Historical memberships must come from the exact endpoint assessment, not a September-only set reused for March.

Contributor pages repeat the complete same binding and digest. `cell.contributor_set_id`, `point.contributor_set_reference` and the page set must agree (or both cell/point are null where contributor disclosure is unavailable). Wrong digest, incompatible endpoint assessment/input lineage, or conflicting references fails semantic acceptance even if shape-valid. Count scalar contributor size equals its included count; sums/durations carry the appropriate entry/known-observation set, not the summed value.

The companion normalises Data's metric point and result semantics; it does not mutate v0.2. For baseline measures, the adapter maps the legacy query/result exactly, retaining the legacy immutable result reference when one is stored. Five analytical additions and seven experience additions live in `measure-additions.json@1.0.0`. Visual IDs are not metric IDs. Unregistered definitions or undeclared/inapplicable parameters return `DEFINITION_UNAVAILABLE` or `INVALID_REQUEST`; generic free-form model filters are forbidden.

Default confirmed totals include only supported `included` memberships. Uncertain/excluded candidates remain separate review populations and coverage. Parent reach and Any are case unions; All is intersection. Distinct members are recomputed over the selection, with unknown identity disclosed. `active_in_window` requires a supported interval overlapping the window; `active_at_endpoint` requires supported active state immediately before B; `all_linked_to_date` preserves supported historical associations available by T. Missing completion is not an open-ended unresolved interval. Unknown boundaries cannot support inclusion merely because the case is open; explicit current evidence may support endpoint state without a complete historical interval.

Exact combinations use one taxonomy level. Each assessed case contributes once to its exact **observed supported** set; `{A}` with uncertain B is labelled observed A with uncertainty, never proved exclusively A. Distinguish assessed-no-supported-membership from unassessed; do not classify missing evidence as none. `full_level` includes all level nodes, even outside selected issue filters. `selected_only` is visibly a projected set and never advertised as the full combination. Top K sorts descending count then lexicographic sorted node IDs; remainder is the union of other sets. K + remainder + declared none/unassessed groups reconcile to the selected population. Drill-down on remainder returns its actual union.

Contributor paging binds result/cell/predicate and stable ordered entity IDs; opaque cursor carries these server-side, a maximum 100 items per page, full eligible total, no page-only totals. Reauthorise every page. A policy change invalidates the context/result handle; do not return a newly reduced page under the old unchanged count. Duplicate/skip detection and count/contributor parity are acceptance checks. Aggregate-only results contain no identifying contributor references; contributor requests return neutral `RESOURCE_UNAVAILABLE`.

Coverage has explicit `entity_unit` and `dimension`. Eligible candidates partition into included, excluded, uncertain and missing within **one stated unit/dimension**, with no double counting; if a definition uses overlapping reason flags, record them separately. `additional_coverage` can describe different units/dimensions and is never summed into the primary partition. A days distribution counts case observations; member reach may separately disclose request occasions lacking identity, without treating them as distinct missing members. Zero is valid only for a completely assessed eligible population under the declared feed coverage. Partial observed sums use `partial` with limitations. Coverage inspectors do not upgrade a missing feed to zero. Percent changes require identical units, compatible scope, taxonomy, periods/modes and coverage; zero prior means percentage unavailable, with absolute difference only where valid.

## 7. Age, closures and distributions — O-07

Original receipt is the default age basis. Team receipt is a labelled alternative for the entire query, never a per-case fallback. Local-calendar-day age retains original receipt through reopenings. At an exclusive midnight stock endpoint, age uses the immediately preceding local calendar date; at a nonmidnight endpoint it uses that local date. An inclusive ordinary cutoff uses its own local date. Compute by calendar dates, not subtracting a fixed 24 hours; partial cells use their actual effective endpoint. Open-spell age, dependency elapsed time, AFCA age and service completion remain separate. Missing and inconsistent/negative endpoints are disclosed, excluded from known durations and never clamped to zero.

For sorted known values x1…xn, R7 quantile uses h=1+(n−1)p, interpolation between floor(h) and ceil(h). n=1 returns that value; n=0 returns null for every statistic. This gives the accepted median rule. Publish total/known/missing N and min, p25, median, p75, p90, max; no extrapolation. Do not draw a smooth density or a boxplot tail from nonexistent observations. Open-age distributions are inventory, not estimated resolution time; completed-duration distributions disclose still-open cases separately, with no fabricated closure or survival estimate.

`cases.closure_transitions`: genuine sourced nonclosed→closed event, counted once by transition occurrence. Reclose after a genuine reopening is another transition; repeated closed status/copies are not. Unknown predecessor/order remains uncertain. Not every closure proves service fulfilment.

Baseline `cases.closed_duration@0.2.0`: unique cases with a supported closure in the period **and a supported latest administrative state closed at the selected evidence cutoff**. Still-open/awaiting/reopened and unknown/conflicting states are excluded/disclosed. Select the last supported closure in the window for each eligible case. The companion `cases.selected_closure_duration@1.0.0` is deliberately a different cohort: it includes cases with a supported closure in the window even when subsequently reopened at the cutoff. It also selects the last closure in the window per case and shows subsequent reopening independently. Never relabel a legacy result as this new definition. Each distribution counts unique cases, not transitions; the table identifies the selected closure. Default duration is original receipt→selected administrative closure, not service completion. Alternative open-spell→closure is explicitly labelled. No closure series is inferred by subtracting backlog stocks.

## 8. Handling relationships and impact

Three separate relation types: `co_occurrence`, `ordered_follow_on`, `supported_operational_consequence`. Shared tags or chronology alone cannot establish the last. Ordered association requires sourced order; operational consequence additionally requires evidence of the specific consequence, contradictions and alternatives. A result names its chosen relation type. Each matrix cell counts a case union; cells overlap and cannot be summed into a portfolio total. Legal fault, intentional discrimination, avoidable time and causal savings are separate unsupported propositions unless separately evidenced and reviewed.

Keep baseline recorded seconds, cash payments/reversals and obligations intact. No double counting source copies, shared AFCA matters or invoice plus payment. Linked issue burden can overlap; overall impact uses contributor unions. Principal benefit amounts, capacity estimates, future fee estimates and hypothetical savings never enter recorded complaint cash. No fines/lawsuit/retention savings are fabricated. The demo's parallel universes may compare a competent baseline and the proposed workflow on identical evidence; a mitigation scenario is labelled assumption-driven and cannot prove millions saved.

## 9. API behaviour and UI state

Twelve reusable read/query operations in `shared.schema.json`. Recommended transport is authenticated `POST /v1/operations` with typed `operation` discriminator; binary retrieval uses the opaque returned action. POST here does not author evidence or enact operational decisions. Transport may change without changing semantic operations only through a recorded compatible revision.

| Operation | Resolved boundary |
|---|---|
| `context.resolve` | Root scope or child context from exact `population_reference`; server verifies result/cell/hash, clips evidence/analysis to its binding and returns explicit origin/boundary. Requested preferences cannot widen a child context. |
| `analysis.query` | Definition and typed filters; optional exact population reference intersects/crosswalks that frozen selection into the measure's units. Issue/case-linked impact uses the same accepted case set and versioned links, not freshly inferred latest membership. |
| `findings.list` | One homogeneous paged `items` stream filtered by explicit kinds and dispositions, case/result/cell selection; each referenced record resolved at the same context. Uncertain/excluded review populations are not silently merged with included contributors. |
| `contributors.list` | Exact result/cell and complete immutable population binding with stable pages. |
| `taxonomy.get` | Exact permitted catalogue: stable node/level/label/definition/parent/aliases/dimension/finding references. A rename keeps identity; split/merge changes require version/migration and compatibility rules. No unavailable-version fixture fallback. |
| `case.get` | Trusted four-dimensional state projection and a paged timeline of evidenced business events; sources are not automatically events. |
| `case.sources.list` | Exhaustive permitted **source** inventory, including uncited/source-only summaries. Separate from timeline, findings and asset existence. |
| `case.files.list` | Unique permitted asset inventory, including extraction-failed files and reused attachments, with permitted parents and mapping/extraction states. Unheld advertisement is source metadata, never a fake asset. |
| `entity.get` | Exact accepted observation/fact/financial/work/MX/AFCA entity resolved within the immutable context; optional requested immutable record must match. Returns selected record and independently paged permitted links. Shared AFCA matter is retrieved once by its real identity. |
| `source.get` | Exact source and optional citation; null citation supports inventory/full-source browsing. |
| `asset.get` | Permitted retrieval action with compatible version, expiry and current authority. |
| `location.resolve` | Exact authorised citation/extraction/original binding, verified or explicit unmapped/invalid state. |

Source inventory, asset inventory, case timeline and analysis list each have an independent stable stream/cursor and full **permitted** total; no mixed-array paging. Order inventories by immutable identity; timeline by supported time/precision then event ID, displaying unknown/overlapping timing rather than asserting an invented order. Related-record pages preserve their own stream ID. End-of-stream `next_cursor=null` means exhausted returned stream; `completeness` separately describes source/extraction/history coverage, not absence of inaccessible objects. A source without a classified event/finding remains in inventory; an asset with failed extraction remains in files. Cross-page references resolve by `source.get`/`entity.get`, never by assuming the first page is complete. Cursor binds kind/filter/scope/version and is invalidated on authority changes.

Use `context.resolve(population_reference)` after a chart-cell click to obtain its restricted child context without changing global UI filters. All case/source/entity/file operations then use that child context; their details cannot import later evidence. The originating global selection remains visible as a breadcrumb. Inspecting later evidence requires an explicit new context/action. For downstream impact `analysis.query(population_reference)` must preserve the frozen population and inherit its endpoint lineage; any additionally requested filter only narrows. Exact unit crosswalks follow source-backed case↔ledger/work/matter links and preserve union dedupe. Root portfolio impact has no population reference.

Context resolution binds permissions, release, evidence cutoff and mode. Requests refer to `context_id`; they cannot supply policy grants. Analysis queries calculate deterministic results from compatible published analysis; they do not start unconstrained LLM investigations per browser refresh. Long-running analysis is an independent controlled pipeline. Source payload must be a source record, case payload a case record, and listed/entity records must match their accepted kind filters: broad v0.2 schema references require these additional semantic checks.

Case state projection is a trusted, versioned source-linked resolution output, not browser inference. Administrative state uses supported temporal state transitions/known corrections, with unknown/conflict preserved. Merits is scoped per decision target; service separates assertions, confirmation and contradiction per action target; responses retain respondent/target/dimension without a global satisfaction classification. Closure never proves execution; an execution assertion alone never proves confirmation; an update-only response never proves service acceptance. Unresolved targets and `no_evidenced_response` are explicit limitations, not fabricated response occasions. The resolver must cite its rule/version and accepted underlying observations; unresolved contradictions block a convenient completed state. These projection propositions have independent coverage and do not upgrade one another.

Supported definition references and response dimensions are service capabilities, not proof of populated complete data. Unsupported dimension is unavailable, not silently substituted. Taxonomy comes from a versioned accepted analysis catalogue, with stable node IDs, parent hierarchy/aliases and source-backed findings; source tags, filenames and private incident assignments cannot become accepted nodes automatically. Case-get timeline events include all permitted history through the cutoff, with activity-period highlighting rather than deletion of older context. Companion member-experience/target records and interval/relationship references are retrieved through permitted finding/source detail compositions and their accepted analysis set; they must be available in case detail when supported.

`ok` carries a typed payload and compatible context. `unavailable` carries a safe typed reason; denied and nonexistent resources both return `RESOURCE_UNAVAILABLE` with identical outward behaviour. Integrity/unsupported reasons are returned only after authorised discovery. Do not expose restricted resource IDs, paths, filenames or detailed internal errors. Trace/correlation IDs go to trusted logs. Expired contexts require resolution again.

UI states: no release; not calculated; partial coverage; empty fully assessed population; denied/missing resource; unsupported original; pending/failed extraction; unmapped location; stale/incompatible result; genuine internal failure. They are distinct from zero. Only last completed compatible permitted results may remain, labelled with their actual snapshot/version. Source citation, full extraction and original file are separate actions. Drill-down preserves originating result/cell, filters, versions, evidence cutoff, mode and navigation context; never silently replaces them with “latest”.

## 10. Publication and acceptance — O-08

An internal immutable allowlisted release enumerates exact accepted objects and byte digests; no recursive Data-folder ingestion. Case/source/procedure/coverage and accepted companion assets are published first; analysis is a separately accepted immutable set. Audit/private gold is never included. Manifest validation checks existence, approved storage prefixes, digest/size, kind and acceptance references; no planning placeholder passes. Empty analysis is an explicit uncalculated state, not zero findings.

Acceptance layers: contract shape/semantics; source review; byte/extraction fidelity; independent evidence-conditioned diagnostic gold; deterministic exact entity/cents/seconds/quantile parity; permission/historical replay; rendered connected UI journey. Contract tests cover examples and rejection rules, not production access enforcement or diagnostic accuracy. Owner acceptance must name the package manifest digest/version and any limits. Silence is not approval. Changes after freeze need a new version and compatibility/regression review.

No remaining human product choice blocks the essential build. Technical owners review this package; actual source writing and UI implementation follow their own authorised coding tasks. Optional chat/scenario/export/retention/survey features are later scope, not a reason to delay the core evidence-backed dashboard.
